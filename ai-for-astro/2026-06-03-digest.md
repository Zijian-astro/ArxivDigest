## 1. Cost-Aware Query Routing in RAG: Empirical Analysis of Retrieval Depth Tradeoffs

- arXiv ID: `2606.02581`
- Authors: Sanjay Mishra
- Score: 9
- Link: https://arxiv.org/abs/2606.02581
- PDF: https://arxiv.org/pdf/2606.02581
- Subjects: Information Retrieval (cs.IR) ; Artificial Intelligence (cs.AI)
- Reason: Directly addresses cost-aware query routing in RAG, a key component for building efficient LLM-based research agents for astronomy literature review and data analysis.

Short digest:
This paper tackles the problem of balancing retrieval depth, latency, and cost in retrieval-augmented generation (RAG) systems. It introduces Cost-Aware RAG (CA-RAG), a framework that dynamically selects a retrieval strategy (from no retrieval to top-10 dense retrieval) per query based on a utility score that combines estimated answer quality, latency, and token cost. For astronomy, this could enable building a research agent that efficiently queries a large corpus of papers, data catalogs, or instrument documentation without wasting compute on simple lookups while still providing deep context for complex questions. A concrete workflow would be an agent that helps analyze JWST spectra: a simple query like 'what is the redshift of GN-z11?' uses a cheap direct answer, while a complex query like 'compare the SED fitting results for little red dots across three different codes' triggers deep retrieval. The main caveat is that the router's quality prior must be calibrated to the specific domain (astronomy QA), and the benchmark used is small (28 queries), so domain-specific validation is needed.

Full-text inspection checklist:
- Check whether the quality prior is learned from human annotations or heuristics, and whether it could be adapted to astronomy-specific QA datasets.
- Look for the per-query delta analysis to understand which query types drive cost savings and whether those types map to common astronomy questions.
- Examine the sensitivity analysis to see how the cost-latency-quality tradeoff shifts when the utility weights are tuned for a research agent use case.

## 2. Uncertainty-Aware Clarification in LLM Agents with Information Gain

- arXiv ID: `2606.03135`
- Authors: Mengyi Deng , Zhiwei Li , Xin Li , Tingyu Zhu , Ying Zhao , Zhijiang Guo , Wei Wang
- Score: 8
- Link: https://arxiv.org/abs/2606.03135
- PDF: https://arxiv.org/pdf/2606.03135
- Subjects: Artificial Intelligence (cs.AI)
- Reason: Directly addresses uncertainty quantification and goal-oriented clarification in LLM agents, which is highly relevant to building reliable research agents for astronomy workflows.

Short digest:
This paper tackles the problem of LLM agents making erroneous tool actions when user instructions are underspecified due to latent uncertainty over intent. The core idea is a goal-oriented clarification framework that uses an Information Gain Reward metric, which quantifies how much a clarification question reduces uncertainty about the true goal by measuring Bayesian belief updates. For astronomy, this could help build agents that ask clarifying questions when a researcher gives vague instructions for data analysis or literature search, reducing errors in automated workflows. A concrete workflow would be an agent that, when asked to 'find interesting high-redshift galaxies,' asks clarifying questions about redshift range, selection criteria, or data source before querying a catalog. A key caveat is that the framework was validated in a simplified tool-use environment (τ-Bench) and may need adaptation to handle the complexity of astronomical databases and analysis tools.

Full-text inspection checklist:
- Check whether the Information Gain Reward is computed using a tractable approximation or exact Bayesian inference, and whether it scales to large action spaces.
- Look for details on how the clarifier is trained and whether the reward model requires a separate dataset of user intents.
- Examine the cross-agent evaluation results to see if performance gains hold across different LLM backbones relevant to astronomy (e.g., open-source models).

## 3. APIC: Amortized Physics-Informed Calibration using Neural Processes

- arXiv ID: `2606.03355`
- Authors: Aishwarya Venkataramanan , Sai Karthikeya Vemuri , Joachim Denzler
- Score: 8
- Link: https://arxiv.org/abs/2606.03355
- PDF: https://arxiv.org/pdf/2606.03355
- Subjects: Machine Learning (cs.LG)
- Reason: Amortized physics-informed calibration directly addresses systematic discrepancies between models and observations, a core problem in astrophysics (e.g., SED fitting, galaxy formation models).

Short digest:
This paper proposes a method to calibrate physics models by learning systematic discrepancies across many related systems. The main idea uses Neural Processes for amortized Bayesian inference, disentangling physical parameters from shared structural errors. For astronomy, this could calibrate galaxy formation simulations against observations, or improve SED fitting by learning systematic biases in stellar population models. The method is demonstrated on ODEs and PDEs, not astrophysical models. A prerequisite is a differentiable physics simulator or a surrogate model.

Full-text inspection checklist:
- Check if the method scales to high-dimensional parameter spaces (e.g., >100 parameters).
- Look for experiments on real-world data with known systematic errors, not just synthetic.

## 4. A Fast Methane Detection Pipeline on Board Satellites Based on Mag1c-SAS and LinkNet

- arXiv ID: `2606.03675`
- Authors: Jonáš Herec , Vít Růžička , Rado Pitoňák , Jan Sedmidubsky
- Score: 8
- Link: https://arxiv.org/abs/2606.03675
- PDF: https://arxiv.org/pdf/2606.03675
- Subjects: Computer Vision and Pattern Recognition (cs.CV)
- Reason: Directly relevant: fast methane detection on satellites using hyperspectral imagery, with methods transferable to astronomical source detection and onboard processing.

Short digest:
This paper aims to enable fast methane detection from hyperspectral satellite imagery onboard resource-limited hardware, which is crucial for timely climate action. It accelerates the Mag1c algorithm (Mag1c-SAS, ~80x faster) and pairs it with a lightweight LinkNet neural network to reduce noise. The methods are evaluated on real satellite data and shown to be viable for onboard processing with low power consumption. For astronomy, the same approach could be applied to onboard detection of transient events (e.g., supernovae, GRB afterglows) in survey data from missions like Roman or Euclid, or to real-time spectral feature detection. The caveat is that the method is tuned for methane absorption features, so adaptation to astronomical spectral lines would require retraining on appropriate data.

Full-text inspection checklist:
- Check the band selection strategies and whether they can be adapted for astronomical spectral lines
- Look at the hardware profiling results to assess feasibility for space-based platforms
- Examine the LinkNet architecture and whether it can be replaced with a model trained on astronomical data
- Review the EMIT-MSeg dataset annotation strategy for potential adaptation to astronomical segmentation tasks

## 5. Agent libOS: A Library-OS-Inspired Runtime for Long-Running, Capability-Controlled LLM Agents

- arXiv ID: `2606.03895`
- Authors: Yingqi Zhang
- Score: 8
- Link: https://arxiv.org/abs/2606.03895
- PDF: https://arxiv.org/pdf/2606.03895
- Subjects: Operating Systems (cs.OS) ; Artificial Intelligence (cs.AI); Cryptography and Security (cs.CR)
- Reason: The paper designs a runtime system for long-running, capability-controlled LLM agents, which is directly relevant to building reliable research agents for automated scientific discovery.

Short digest:
The paper asks how to build a runtime system for LLM agents that can maintain state across model calls, fork subtasks, wait for events, and be safely resumed and audited. It introduces Agent libOS, which treats an agent as an AgentProcess with identity, lifecycle, typed memory, explicit capabilities, and audit records. For astronomy, this could provide the infrastructure for a research agent that runs long-lived data analysis workflows, e.g., a multi-step SED fitting pipeline that queries databases, runs models, and waits for human approval. The key design principle is that tools are like libc wrappers and runtime primitives enforce the authority boundary, which is crucial for safe autonomous operation. A major caveat is that the current prototype is Python-based and has 123 regression tests, but it has not been tested on astronomical workflows; adapting it would require wrapping astronomical tools and defining appropriate capability policies.

Full-text inspection checklist:
- Check whether the AgentProcess model supports checkpointing and resumption of long-running scientific computations.
- Look for details on the capability system: can it enforce fine-grained permissions for astronomical database access or pipeline execution?
- Assess the Object Memory: can it store and retrieve astronomical data products (images, spectra, catalogs)?
- Check whether the runtime supports integration with existing astronomical software (astropy, JWST pipeline, etc.) via the tool system.
