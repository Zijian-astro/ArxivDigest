## 1. Trust or Abstain? A Self-Aware RAG Approach

- arXiv ID: `2605.18792`
- Authors: Xi Zhu , Ziqi Wang , Kai Mei , Wujiang Xu , Minghao Guo , Bangji Yang , Jiajun Fan , Dimitris N. Metaxas
- Score: 9
- Link: https://arxiv.org/abs/2605.18792
- PDF: https://arxiv.org/pdf/2605.18792
- Subjects: Information Retrieval (cs.IR) ; Computation and Language (cs.CL)
- Reason: Directly addresses knowledge conflicts in RAG, which is critical for building reliable LLM agents that combine parametric knowledge (e.g., from training) with retrieved evidence (e.g., from papers or databases) in astronomy.

Short digest:
This paper tackles the problem of knowledge conflicts in RAG, where retrieved evidence and the LLM's internal knowledge disagree or are both unreliable, which is a key challenge for scientific question answering. The authors introduce SABER, a self-aware belief estimator that requires no LLM fine-tuning, combining a self-prior with conditional reasoning representations from multi-trace inference to decide whether to trust parametric knowledge, retrieved knowledge, either, or abstain. For astronomy, this is highly relevant because an LLM agent analyzing JWST data might retrieve conflicting information from the literature (e.g., different redshift estimates for the same source) and needs a principled way to decide what to trust. A concrete workflow would be using SABER in a research agent that queries ADS for papers about a specific high-redshift galaxy and must reconcile conflicting claims about its properties. A caveat is that SABER requires constructing a knowledge-conflict benchmark specific to the LLM backbone, which may be non-trivial for astronomy-specific models.

Full-text inspection checklist:
- Check how the 4-cell decision (trust PK, trust CK, trust either, abstain) is implemented and whether it can be adapted to astronomy-specific knowledge sources.
- Look for the construction of the knowledge-conflict benchmark and assess whether a similar benchmark could be built from astronomical datasets (e.g., conflicting redshift measurements).
- Examine the risk-coverage curve and abstention mechanism to see if it can be tuned for high-stakes scientific decisions where false positives are costly.

## 2. How Far Are We From True Auto-Research?

- arXiv ID: `2605.19156`
- Authors: Zhengxin Zhang , Ning Wang , Sainyam Galhotra , Claire Cardie
- Score: 9
- Link: https://arxiv.org/abs/2605.19156
- PDF: https://arxiv.org/pdf/2605.19156
- Subjects: Artificial Intelligence (cs.AI) ; Computers and Society (cs.CY); Machine Learning (cs.LG); Multiagent Systems (cs.MA)
- Reason: Directly evaluates LLM agents for automated research, a core interest. The paper's focus on agent-generated papers, experimental rigor, and failure modes (fabrication, underpowered experiments) is highly relevant to building trustworthy research agents for astronomy.

Short digest:
This paper asks how close current AI agents are to producing truly acceptable research papers autonomously. The authors built ResearchArena, a minimal system that lets LLM agents (Claude, GPT, Kimi) complete the full research loop—ideation, experiments, writing, and revision—with only light guidance. They generated 117 papers across computer science topics and evaluated them with automated review, artifact-aware peer review, and human meta-review. While automated scores looked promising, manual inspection revealed severe flaws: fabricated results, underpowered experiments, and mismatches between plans and executions. None of the 117 papers met the acceptance bar for a top venue. For astronomy, this work is a cautionary tale: it shows that current agents can produce plausible-looking papers but fail on experimental rigor, a critical issue if we want to use agents for JWST data analysis or literature synthesis. Before adopting such agents, one should check whether the agent's outputs include verifiable evidence (e.g., actual code outputs, data files) and whether the agent can be audited for fabrication. The main caveat is that the study uses computer science seeds, not astronomy; the failure modes may differ in data-driven fields.

Full-text inspection checklist:
- Check the taxonomy of failure modes (fabricated results, underpowered experiments, plan/execution mismatch) and see if they map to astronomy workflows.
- Look for the artifact-aware peer review methodology: how does the agent's workspace get inspected alongside the manuscript?
- Examine the SAR (manuscript-only reviewer) vs. artifact-aware PR score gap to understand how much automated review overestimates quality.

## 3. Query-Aware Flow Diffusion for Graph-Based RAG with Retrieval Guarantees

- arXiv ID: `2605.18775`
- Authors: Zhuoping Zhou , Davoud Ataee Tarzanagh , Sima Didari , Wenjun Hu , Baruch Gutow , Oxana Verkholyak , Masoud Faraki , Heng Hao , Hankyu Moon , Seungjai Min
- Score: 8
- Link: https://arxiv.org/abs/2605.18775
- PDF: https://arxiv.org/pdf/2605.18775
- Subjects: Information Retrieval (cs.IR) ; Artificial Intelligence (cs.AI)
- Reason: Directly addresses graph-based RAG, a method that could be applied to astronomical knowledge graphs for multi-hop reasoning over literature or multi-wavelength catalogs.

Short digest:
This paper tackles the problem of retrieving relevant subgraphs from a knowledge graph for question answering, where existing methods use heuristics or static exploration that ignore the query's meaning. The authors propose QAFD-RAG, a training-free method that dynamically weights graph edges by how well they align with the query's semantic embedding, guiding retrieval along relevant paths. This approach provides the first statistical guarantees for query-aware graph retrieval, converging exponentially fast with complexity scaling only with the subgraph size. For astronomy, this could enable an LLM agent to traverse a graph of papers, objects, and observations to answer complex multi-hop questions like 'Which JWST NIRSpec observations of little red dots have published SED fits?' A concrete workflow would be building a knowledge graph from ADS abstracts, JWST data products, and catalogs, then using QAFD-RAG to retrieve relevant subgraphs for a research agent. A caveat is that the method assumes a pre-existing graph with meaningful edge semantics, and building such a graph for astronomy is a significant upfront investment.

Full-text inspection checklist:
- Check whether the paper provides an explicit algorithm for query-aware edge weighting that could be implemented on a custom graph.
- Look for the signal-to-noise conditions required for the retrieval guarantee and assess whether astronomical data would meet them.
- Examine the question-answering experiments to see if the method handles multi-hop queries that span different data types (e.g., images, spectra, catalogs).

## 4. ReCrit: Transition-Aware Reinforcement Learning for Scientific Critic Reasoning

- arXiv ID: `2605.18799`
- Authors: Wanghan Xu , Yuhao Zhou , Hengyuan Zhao , Shuo Li , Dianzhi Yu , Zhenfei Yin , Yaowen Hu , Fengli Xu , Wanli Ouyang , Wenlong Zhang , Lei Bai
- Score: 8
- Link: https://arxiv.org/abs/2605.18799
- PDF: https://arxiv.org/pdf/2605.18799
- Subjects: Machine Learning (cs.LG) ; Artificial Intelligence (cs.AI); Computation and Language (cs.CL)
- Reason: Directly addresses LLM critic interaction in scientific reasoning, which is crucial for building reliable research agents that can handle user feedback and correct mistakes without abandoning correct answers.

Short digest:
This paper tackles the problem of LLMs abandoning correct scientific solutions after user criticism, which is especially risky in scientific reasoning. The authors propose ReCrit, a transition-aware reinforcement learning framework that decomposes Initial-to-Critic behavior into four quadrants (Correction, Sycophancy, Robustness, Boundary) and rewards correction and robustness while penalizing sycophancy. For astronomy, this is highly relevant for building research agents that interact with astronomers: an agent should accept valid corrections but resist incorrect criticism (e.g., a user claiming a redshift is wrong when it is correct). A concrete workflow would be an agent that presents a SED fit result and must decide whether to update its answer based on user feedback. A caveat is that the method requires training with a reward model that can distinguish correction from sycophancy, which may be difficult to construct for astronomy-specific tasks.

Full-text inspection checklist:
- Check how the four quadrants are defined and whether the reward model is task-specific or general.
- Look for the dynamic asynchronous rollout mechanism and assess whether it can be applied to long scientific reasoning chains.
- Examine the benchmarks (ChemBench, TRQA, EarthSE) to see if they include tasks similar to astronomy (e.g., interpreting spectra or images).

- Authors: Renuka Chintalapati , Sid Raskar , Anurag Acharya , Jared Willard , Patrick Emami , Sameera Horawalavithana
- Score: 8
- Link: https://arxiv.org/abs/2605.18854
- PDF: https://arxiv.org/pdf/2605.18854
- Subjects: Machine Learning (cs.LG)
- Reason: Directly evaluates memory condensation strategies for coding agents in scientific discovery, highly relevant for building automated research agents for astronomy.

Short digest:
This paper systematically evaluates eight memory condensation strategies for coding agents on 60 scientific discovery tasks across six domains. It finds that no condenser significantly improves hypothesis quality, while LLM-based condensers increase token costs. Masking tool-call outputs achieves modest savings. The optimal strategy varies by domain and task length. For astronomy, this is directly relevant for designing coding agents that can perform long-running data analysis tasks (e.g., fitting SEDs, reducing JWST images). The main caveat is that the tasks are from DiscoveryBench, not astronomy-specific, so transferability needs verification.

Full-text inspection checklist:
- Check if the evaluation tasks include any astronomy or astrophysics problems.
- Look for details on how memory condensation strategies handle domain-specific context (e.g., FITS files, catalogs).
- Evaluate whether the findings generalize to astronomy-specific coding tasks (e.g., using astropy, JWST pipelines).

## 6. StruMPL: Multi-task Dense Regression under Disjoint Partial Supervision and MNAR Labels

- arXiv ID: `2605.19931`
- Authors: Reza M. Asiyabi , Juan Alberto Molina-Valero , The SEOSAW Partnership , Steven Hancock , Casey M. Ryan
- Score: 8
- Link: https://arxiv.org/abs/2605.19931
- PDF: https://arxiv.org/pdf/2605.19931
- Subjects: Computer Vision and Pattern Recognition (cs.CV) ; Artificial Intelligence (cs.AI); Machine Learning (cs.LG)
- Reason: Directly addresses multi-task regression under partial supervision with missing-not-at-random labels, which is highly relevant to astronomical SED fitting and photometric redshift estimation where labels (spectra) are sparse and biased.

Short digest:
This paper tackles the problem of estimating forest aboveground biomass from Earth observation data, where two label sources are structurally incompatible: spaceborne lidar provides canopy structure but no biomass, and ground plots provide biomass but are biased and sparse. The authors formalize this as multi-task dense regression under disjoint partial supervision with MNAR labels and physical constraints. They propose StruMPL, which uses a shared encoder with per-variable regression, imputation, and propensity heads for spatial MNAR correction, plus a learnable physics module enforcing inter-task constraints. The supervised loss uses Augmented IPW (AIPW) with stop-gradients, reducing high-AGB bias by ~54%. For astronomy, this directly maps to photometric redshift or SED fitting: we have spectroscopic redshifts (like ground plots) at biased locations, and photometric data (like lidar) everywhere. A concrete workflow would be jointly estimating redshift, stellar mass, and star formation rate from multi-band photometry, using sparse spectroscopy as partial labels. A key caveat is the method is validated on forest biomass, not astronomical data, and the physical constraints are allometric (biome-specific), which would need replacement with astrophysical models.

Full-text inspection checklist:
- Check if the AIPW pseudo-outcome formulation is described with enough detail to reimplement
- Look for any discussion of how the physical constraint module is designed and whether it is learnable or fixed
- Assess whether the method scales to high-dimensional outputs (e.g., full SEDs) or only scalar targets
- Look for ablation studies showing the contribution of the propensity and imputation heads separately

## 7. PEEK: Context Map as an Orientation Cache for Long-Context LLM Agents

- arXiv ID: `2605.19932`
- Authors: Zhuohan Gu , Qizheng Zhang , Omar Khattab , Samuel Madden
- Score: 8
- Link: https://arxiv.org/abs/2605.19932
- PDF: https://arxiv.org/pdf/2605.19932
- Subjects: Artificial Intelligence (cs.AI) ; Computation and Language (cs.CL); Machine Learning (cs.LG)
- Reason: PEEK directly addresses the problem of LLM agents operating over long and recurring external contexts, which is highly relevant to building research agents for astronomy that need to repeatedly access large document corpora, catalogs, or code repositories.

Short digest:
1. The paper asks how LLM agents can efficiently reuse knowledge about a recurring external context (like a document corpus or codebase) across multiple invocations. 2. It introduces PEEK, a system that maintains a small, constant-sized 'context map' in the agent's prompt, which is updated by a programmable cache policy that distills, structures, and evicts information to keep the agent oriented. 3. For astronomy, this could enable an agent that repeatedly works with a large JWST data archive or a set of galaxy catalogs to avoid re-reading the same metadata and instead maintain a persistent, evolving summary of what is where. 4. A concrete workflow would be an LLM agent that performs iterative SED fitting or source classification across many targets from a large survey, using PEEK to remember which filters, templates, or prior results were useful. 5. The main caveat is that PEEK is designed for 'recurring same-context workloads' and may not help for one-shot queries; also, the paper tests on coding and reasoning benchmarks, not scientific data, so the transfer to astronomy-specific contexts would need validation.

Full-text inspection checklist:
- Check whether the context map is interpretable (e.g., can we inspect what knowledge is cached about a JWST catalog?)
- Look for experiments that test PEEK on tasks requiring repeated access to structured scientific data (e.g., tables, catalogs) rather than only code or text.
- Examine the token budget and eviction policy to see if it can handle the scale of a large astronomical dataset (e.g., millions of sources).
