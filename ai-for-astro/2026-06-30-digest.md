## 1. Hierarchical Experimentalist Agents

- arXiv ID: `2606.29315`
- Authors: Abhranil Chandra , Sankaran Vaidyanathan , Utsav Dhanuka , Varun Gandhi , Scott Niekum
- Score: 9
- Link: https://arxiv.org/abs/2606.29315
- PDF: https://arxiv.org/pdf/2606.29315
- Subjects: Artificial Intelligence (cs.AI) ; Machine Learning (cs.LG)
- Reason: Directly proposes an LLM agent framework for active experimentation and skill learning, which is highly relevant to automated scientific discovery.

Short digest:
This paper introduces Hierarchical Experimentalist Agents (HExA), an in-context self-improvement framework that enables LLM agents to learn from active experimentation in novel domains. HExA iteratively designs experiments, learns reusable skills, and integrates evidence to answer queries, all without training or external supervision. For astronomy, this could automate the process of testing hypotheses about astronomical phenomena, such as designing observations to distinguish between AGN and starburst models. A concrete workflow could be using HExA to propose and test galaxy formation scenarios by querying simulation APIs or observational databases. The main caveat is that HExA is evaluated on a 2D physics benchmark (PHYRE), not on real astronomical data or simulations, so its performance on complex astrophysical workflows is unknown.

Full-text inspection checklist:
- Check if the paper provides any analysis of how HExA handles noisy or incomplete feedback, as astronomical data often has high uncertainty
- Look for details on the skill library structure and whether skills can be composed for multi-step astrophysical workflows
- Examine the computational cost of the iterative experimentation loop, as astronomical simulations can be expensive

It introduces DEEPMED Search, an open-source agentic platform that uses a source-adaptive router to dispatch sub-queries to different databases and an introspective verification module (causal-consistent multi-agent debate) to validate retrieved evidence before synthesis. 3. This matters for astronomy because it provides a transparent, glass-box framework for automated literature review and data synthesis, which could be adapted for tasks like cross-matching catalogs, extracting physical parameters from papers, or building knowledge bases for high-redshift galaxy studies. 4. ## 3. RADIANT-PET: Reasoning-Augmented PET/CT Lesion Segmentation with Large Language Models and Reinforcement Learning

- arXiv ID: `2606.28392`
- Authors: Jiasheng Wang , Tanun Jitwatcharakomol , Piyawadee Jongpradubgiat , Simeng Zhu
- Score: 8
- Link: https://arxiv.org/abs/2606.28392
- PDF: https://arxiv.org/pdf/2606.28392
- Subjects: Computer Vision and Pattern Recognition (cs.CV) ; Artificial Intelligence (cs.AI); Machine Learning (cs.LG)
- Reason: Directly combines segmentation with LLM reasoning for medical imaging, which is highly transferable to astronomical source detection and classification (e.g., AGN vs. artifacts in JWST).

Short digest:
The paper asks how to reduce false positives in PET/CT lesion segmentation by adding an LLM reasoning layer. It first generates candidate uptake regions with a permissive segmentation model, then converts them into structured text descriptions of intensity, morphology, and anatomy, and uses an LLM to classify each as true lesion or false positive. For astronomy, this could be applied to JWST source detection: a permissive segmentation finds all candidate sources (including artifacts and noise peaks), then an LLM reasons about morphology, color, and context to flag true high-redshift galaxies or AGN. A concrete workflow would be running Source Extractor on a JWST image, converting each detection into a text description, and using an LLM to filter out diffraction spikes and hot pixels. A key caveat is that the method relies on structured text descriptions of candidate regions, which requires a well-defined mapping from image features to text; the paper also uses radiology reports as additional context, which has no direct analog in astronomy.

Full-text inspection checklist:
- Look for the exact format of the structured textual descriptions: what features (intensity, morphology, context) are included and how they are extracted from the segmentation output.
- Check whether the LLM is used zero-shot or fine-tuned, and whether the reinforcement learning step (GRPO) is essential or could be omitted for a new domain. Also check if the method requires a radiology report or can work with only image-derived text.

## 6. Covering the Unseen: Information Demand Coverage Optimization for Retrieval-Augmented Generation

- arXiv ID: `2606.29328`
- Authors: Bingxue Zhang , Jianying Jia , Feida Zhu
- Score: 8
- Link: https://arxiv.org/abs/2606.29328
- PDF: https://arxiv.org/pdf/2606.29328
- Subjects: Information Retrieval (cs.IR) ; Artificial Intelligence (cs.AI)
- Reason: Proposes a novel RAG method for complex queries that could directly improve literature review and data analysis in astronomy.

Short digest:
This paper introduces GeoRAG, which recasts context selection in retrieval-augmented generation as an information demand coverage optimization problem. Instead of ranking chunks against a single query, GeoRAG builds a multi-dimensional demand distribution via diverse sub-query generation and selects context by minimizing the Sinkhorn-Wasserstein distance to coverage. For astronomy, this could dramatically improve RAG systems for complex multi-hop questions like 'What are the spectral properties of little red dots at z>7?' by ensuring all sub-aspects are covered. A concrete workflow would be using GeoRAG to retrieve relevant papers, spectra, and catalogs for a literature review on high-redshift AGN. The main caveat is that GeoRAG is evaluated on open-domain QA benchmarks, not on scientific or astronomical datasets, so its performance on domain-specific retrieval needs verification.

Full-text inspection checklist:
- Check if the sub-query generation method can be adapted to produce astronomy-relevant sub-questions (e.g., redshift range, wavelength coverage, object type)
- Look for analysis of computational overhead, as generating multiple sub-queries and computing Sinkhorn distances may be expensive for large corpora
- Examine whether the method handles multi-modal retrieval (images, spectra, tables) or only text

## 7. Reliability, Faithfulness, and the Limits of Post-hoc Explanations of Opaque Scientific Models

- arXiv ID: `2606.29346`
- Authors: Nick Oh , Helen Jin
- Score: 8
- Link: https://arxiv.org/abs/2606.29346
- PDF: https://arxiv.org/pdf/2606.29346
- Subjects: Machine Learning (cs.LG)
- Reason: Directly critiques the use of post-hoc explanations (e.g., SHAP, LIME) for interpreting scientific ML models, arguing they cannot reveal true causal structure. This is highly relevant for astronomers using ML to infer physics from JWST data.

Short digest:
This paper asks whether post-hoc explanation methods (like SHAP or LIME) can reliably reveal the true structure of a scientific phenomenon when applied to a trained ML model. The authors argue that even if a model is accurate (reliable) and the explanation faithfully reflects the model, the explanation does not necessarily tell you how the phenomenon actually works—it only tells you what the model learned, which may be spurious correlations. For astronomy, this is a critical warning: if you train a model to predict galaxy redshift from images and then use SHAP to say 'the model uses disk color,' you cannot conclude that disk color physically causes redshift. The paper suggests that such explanations can only generate candidate hypotheses that need external corroboration (e.g., from physical simulations or controlled experiments). Before investing time in this paper, check whether it provides concrete guidelines for when post-hoc explanations are valid or offers alternative validation strategies (e.g., intervention or perturbation tests) that you could apply to your own astronomical ML workflow.

Full-text inspection checklist:
- Look for concrete examples or case studies (e.g., from physics or biology) that illustrate the failure mode of post-hoc explanations.
- Check whether the paper proposes any positive alternative (e.g., causal inference, intervention, or simulation-based validation) for astronomers to adopt.
- Examine the discussion of 'external corroboration'—does it specify what kind of independent evidence is sufficient to validate a structural claim?

## 8. Diagnosing and Repairing Factual Errors in RAG under Budget Constraints

- arXiv ID: `2606.29377`
- Authors: Soroush Hashemifar , Havva Alizadeh Noughabi , Fattane Zarrinkalam , Ali Dehghantanha
- Score: 8
- Link: https://arxiv.org/abs/2606.29377
- PDF: https://arxiv.org/pdf/2606.29377
- Subjects: Artificial Intelligence (cs.AI)
- Reason: Directly addresses RAG reliability, a core technique for grounding LLMs in external evidence, which is key for literature review and data analysis in astronomy.

Short digest:
This paper tackles the problem of factual errors in Retrieval-Augmented Generation (RAG) systems, especially when deployed under budget constraints like limited compute or latency. The authors propose D2R-RAG, a lightweight framework that diagnoses failures by analyzing the query, retrieved evidence, and generated response, then selects a corrective action (e.g., re-retrieval, rewriting) without needing access to internal model weights. For an astronomer, this is directly relevant because RAG is a natural way to ground an LLM in astronomical catalogs, papers, or instrument documentation. You could imagine using D2R-RAG to build a reliable assistant that answers questions about JWST data reduction or galaxy classification, where incorrect answers are costly. A key caveat is that the method is demonstrated on general-domain QA datasets (FEVER, HotpotQA), so its performance on specialized astronomical text and tables remains to be tested.

Full-text inspection checklist:
- Check if the failure diagnosis rules (e.g., missing evidence, weak relevance) are interpretable and could be adapted to domain-specific retrieval corpora.
- Look for the specific corrective actions (e.g., re-retrieval, query rewriting) and whether they are compatible with astronomy-specific retrieval pipelines.
- Examine the accuracy-efficiency trade-off plots to see if the method maintains high accuracy at the low compute budgets typical for individual researchers.
